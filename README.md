# SidAli

A real programming language — compiler + virtual machine — not a website.

SidAli (formerly VOID-0) is a complete language implementation:

```
source .sidali → lexer → parser (AST) → compiler (bytecode) → stack VM → results
```

No `eval` is used anywhere. Everything below actually computes.

## Run it

```bash
npm install
npm run build   # produces a single self-contained index.html (engine inlined)
npm run dev     # serves it at http://localhost:12000
npm test        # 68 tests: arithmetic, control flow, classes, crypto, algebra, native, CLI
```

## Native compilation

SidAli is not only a VM language. `src/compiler/llvm.ts` lowers the AST to real
LLVM IR, which `clang` turns into native machine code. The `sidac` driver wraps
the whole pipeline:

```bash
npm run sidac -- run examples/05-math.sidali          # JIT on the stack VM
npm run sidac -- build hello.sidali                   # -> native x86_64 executable
npm run sidac -- build hello.sidali --target=wasm32 --emit=obj
npm run sidac -- emit-ir hello.sidali                 # print LLVM IR
npm run sidac -- targets                              # list cross targets
```

Cross targets: `x86_64-linux`, `aarch64-linux`, `armv7m-none-eabi`, `cortex-m4`,
`riscv32-none-elf`, `riscv64-none-elf`, `wasm32`, `bpfel`. Freestanding targets
link against the bare-metal HAL in `src/hal/runtime.c` (no libc).

Open the page: an editor on the left writes `.sidali` files, the **Run** button
executes them on the VM, and the right pane shows real computed output plus the
verification layer (BLAKE3 witness, proof anchor, Dilithium signature, ACE budget,
sigma-kernel stability, DNA blob).

## The language

```
let x = 5
let y = 10
let z = x + y
print z                 // 15

function square(n) { return n * n }
print square(7)         // 49
print fib(55)           // 139583862445
print factorial(5)      // 120

if z > 10 { print "big" } else { print "small" }

class Dog extends Animal {
  speak() { return this.name + " barks" }
}
```

Supports: variables/constants, functions & closures, recursion, arrays & objects,
classes with inheritance, `if`/`else`, `while`, `repeat N { }`, `for x in ...`,
`break`/`continue`, `try`/`catch`/`finally`/`throw`, string interpolation
(`"n = ${n}"`), and transcendental AST nodes (`pi(x)`, `e(x)`).

Keywords also accept Arabic spellings (e.g. `متغير`, `دالة`, `اطبع`, `كرر`).

## Native compiler (`sidac`)

The same front end (lexer → parser → AST) also lowers to LLVM IR and real machine
code through `clang`. This is the systems path, independent of the browser VM.

```sh
npm run build:dist                       # build the engine + dist/ release
node bin/sidac.mjs run  examples/05-math.sidali
node bin/sidac.mjs build hello.sidali --target=riscv32-none-elf --emit=obj
node bin/sidac.mjs build hello.sidali --emit=fat --out=universal
node bin/sidac.mjs targets
node bin/sidac.mjs substrates
node bin/sidac.mjs dna .sidali-build/hello
```

`build` runs on the host; `--target` cross-compiles. `--emit=fat` writes a single
`.sda` universal image carrying every substrate (electron, photon, qubit, fluidic,
vacuum, holographic, plasma, energy) with a per-section BLAKE3.

### DNA header

Every image is tagged with a universal physics-level header:

```
[START:SUBSTRATE=photon:ARCH=riscv64:VERSION=1:BLAKE3=<hex>][END]
```

An ELF/object keeps its magic at byte 0 (so the OS loader still runs it); its DNA
header is appended as a trailer and mirrored to a companion `<artifact>.dna`.
A fat `.sda` instead starts with `[SIDALI-FAT:VERSION=1:SECTIONS=n]` followed by
one `[SUBSTRATE=…:ARCH=…:OFFSET=…:LEN=…:BLAKE3=…]` line per section.

### Universal substrates

Non-electron substrates reuse the same IR (`State` + `Transition` + `Energy`) and
lower to a real clang architecture today; the DNA header records the destination
physics. `x86_64`, `aarch64`, `armv7m`, `cortex-m4`, `riscv32`, `riscv64`, `wasm32`,
`bpfel` (object-only), plus `photon-riscv`, `qubit-riscv`, `fluidic-riscv`,
`vacuum-riscv`, `holographic-wasm`, `plasma-arm`, `energy-riscv`.

## Packages

SidAli ships a small package manager. Packages are ordinary `.sidali` sources
under `packages/<name>/` with a `sidali.toml` manifest.

```sh
node bin/sidali.mjs init myapp           # scaffold a project
cd myapp
node bin/sidali.mjs add std crypto       # record dependencies in sidali.toml
node bin/sidali.mjs install              # vendor them, write sidali.lock (BLAKE3 hashes)
node bin/sidali.mjs run                  # resolve `import` and execute
node bin/sidali.mjs build --out=./app    # native compile the whole program
```

`import <name>` is resolved by the driver before compilation: each package's
`src/main.sidali` is spliced ahead of the entry file, recursively, with cycle
detection. The bundled packages are:

| Package | Contents |
| --- | --- |
| `std` | `max`, `min`, `abs`, `clamp`, `gcd`, `lcm`, `pow`, `isqrt` |
| `crypto` | `isPrime`, `modPow`, `fermat`, `countPrimes`, `checksum16` |
| `collections` | `sort16`, `reverse16`, `sum16`, `min16`, `max16`, `contains16` |

Packages are written to compile on both backends: scalar helpers stay untyped,
array helpers declare a fixed size (`[i64; 16]`) so native code can lower them.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/hayaalayaxk-ctrl/sidali/main/dist/install.sh | sh
```

Requires Node ≥ 18. The installer fetches `dist/sidac`, the engine bundles, and
`sidac.wasm` into `~/.sidali`, then prints `sidac version`.
